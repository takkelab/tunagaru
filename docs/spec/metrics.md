# 指標（metrics）

指標は、「良くなったか」を判断するためと、「悪くなったら止める」関門のために記録する。
次の3つの群に分ける。

| 群             | 測るタイミング                                             | 関門の場所                           |
| -------------- | ---------------------------------------------------------- | ------------------------------------ |
| 抽出の品質     | 抽出・プロンプト・モデルを変えたとき（手元で `pnpm eval`） | PRのレビュー（本人が数値を確認する） |
| 費用           | 常時（`cost_ledger` から集計）                             | アプリ内の予算上限                   |
| コードの健全性 | 毎回（`pnpm check`、CI）                                   | `pnpm check` とCI                    |

## 抽出の品質

正解データは `eval/gold/<slug>.yaml` に置く。本人が詳しい作家・音楽家10人分（日本と海外を半々）で、「実際に好きだと公言している人」の一覧と、可能なら出典を書く。

```yaml
subject: { name: 村上春樹, qid: Q<実際のQID> }
likes:
  - { name: レイモンド・カーヴァー, qid: Q<実際のQID>, source: <出典URL> }
  - { name: スコット・フィッツジェラルド, qid: Q<実際のQID> }
not_likes: [] # 抽出されたら誤りと分かっている人（任意）
```

| 指標                | 定義                                                                     | 目安                                         |
| ------------------- | ------------------------------------------------------------------------ | -------------------------------------------- |
| 適合率（precision） | 抽出された線のうち、正解または目視判定で正しいとされたものの割合         | 0.85以上を目標にする                         |
| 再現率（recall）    | 正解の線のうち、抽出できたものの割合                                     | ソースの比較に使う（目標値は設けない）       |
| 引用照合の破棄率    | LLMの出力のうち、引用が本文と一致せず捨てたものの割合                    | 高すぎる場合はプロンプトかモデルの問題を疑う |
| 発言者の取り違え率  | `attribution` か、発言の主語の誤り（インタビュアーの「好き」など）の割合 | 目視判定で数える                             |
| 極性の誤り率        | `dislikes` を `likes` とするなど、極性を誤った割合                       | 目視判定で数える                             |

- 目視判定: `pnpm eval` が `eval/review/<run>.csv` を書き出す（引用を含むので gitignore する。[ADR 0019](../decisions/0019-public-repository-safeguards.md)）。本人が `correct` 列に `y`／`n` を記入し、`pnpm eval --score <run>` で集計に反映する。正解リストにない線でも、目視で正しいとされれば正解として数える。
- 基準値: 採用した構成（[ADR 0006](../decisions/0006-source-and-model-selection-by-evaluation.md)）の値を `metrics/baseline.json` に置く。
- 関門: 抽出・プロンプト・モデルを変えるPRでは、評価レポートの要約を本文に貼る。**適合率が基準値から3ポイント以上下がったら差し戻す**。再現率だけが上がって適合率が下がる変更も、原則として採用しない（「根拠のない線はない方がまし」のため）。
- 評価の費用は、1回あたり100円以内を目安にする。

## 費用

| 指標                             | 定義                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------- |
| 調査1回あたりの費用              | `settled` の円換算を、完了したジョブ数で割ったもの                               |
| 月の累計                         | 当月の `settled` 合計と `reserved` 合計                                          |
| キャッシュヒット率               | 抽出要求のうち、`content_hash × model × prompt_version` のキャッシュで済んだ割合 |
| 事前フィルタの削減率             | 1 −（フィルタ後のトークン数 ÷ フィルタ前のトークン数）                           |
| プロンプトキャッシュの読み取り率 | `cached_input_tokens` ÷ `input_tokens`                                           |

`pnpm cli budget` と S8 の画面で表示する。予算の上限そのものは、アプリが強制する（[data: 予算](data.md#予算)）。

## コードの健全性

`pnpm check` とCIで強制する。

| 指標                                            | 閾値                       | 検出の場所                               |
| ----------------------------------------------- | -------------------------- | ---------------------------------------- |
| 行カバレッジ（`src/domain/`）                   | 90%以上                    | Vitest の `coverage.thresholds`          |
| 行カバレッジ（全体、`src/web/` を除く）         | 70%以上                    | 同上（webはE2Eで担保する）               |
| 依存ルールの違反                                | 0件                        | `pnpm lint:arch`                         |
| 300行を超えるファイル                           | 0件                        | `tools/lint/file-length.mjs`             |
| スキーマのずれ                                  | 0件                        | `tools/schema/gen.mjs --check`           |
| lintを無効化するコメント（`biome-ignore` など） | 新規追加は理由の記述が必須 | Biome の設定（理由のない ignore を禁止） |

## 出力

- `pnpm metrics` は、上の値のうち手元で計算できるもの（カバレッジ、ファイル行数の上位、依存違反の数、当月の費用、最新の評価の要約）を `metrics/latest.json` に書き、表にして標準出力に出す。
- PRの本文には、`pnpm metrics` の表を貼る（[process](process.md#1ステップの流れ)）。
