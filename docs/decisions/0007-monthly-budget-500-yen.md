# 0007 予算は月500円のハード上限とし、費用削減策を必須にする

- 状態: 採用
- 日付: 2026-11-15

## 背景

本人の希望は月500円（約$3.3）。情報量が膨大なので、すべてを事前にDBへ登録するのは難しいのではないか、という懸念もあった。

## 決定

- 月500円をハード上限とする。予約と精算の仕組みで、並行ジョブがあっても超えないようにする（[data](../spec/data.md#予算)）。
- 次の費用削減策を必須にする。
  1. キーワードによる事前フィルタ（送るトークン数を1/5〜1/10にする見込み）
  2. 本文ハッシュによる永続キャッシュ
  3. Wikidata P737 の一括取り込み（無料）
  4. よく辿る人物の事前一括抽出は、Batch API（半額）を使う（ステップ11）
  5. システムプロンプトのプロンプトキャッシュ
  6. Web検索は「深掘り」の場合に限る（[ADR 0006](0006-source-and-model-selection-by-evaluation.md) で確定する）
- 全人物の網羅は目指さない。よく辿る人物から埋める。

## 検討した代替案

- 月$5〜$50の上限: 自由度は上がるが、本人の希望と合わない。
- 上限なしで使用量の表示だけ: 気づかないうちに使いすぎる。

## 結果とトレードオフ

- Haikuで構成Aなら、月に約1,000回調査できる見込み。上位3,000人の一括抽出も、1回きりで$3〜5程度の見込み。
- 上限に達すると、その月は調査できなくなる（表示とキャッシュ済みのデータは使える）。
