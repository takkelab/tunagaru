# 0006 本文ソースとモデルは、Haikuを使った評価で比較して決める

- 状態: 提案（ステップ4の結果で「採用」に更新する）
- 日付: 2026-11-15

## 背景

日本の作家や音楽家が「好き」を語った発言は、Wikipedia よりインタビュー記事に多く残っている。一方、Web検索は費用が最も大きい。2026年11月時点の概算は次のとおり（実装時に再確認すること）。

| 構成                       | Haiku 5.5   | Sonnet 5.5 | Opus 5.5   |
| -------------------------- | ----------- | ---------- | ---------- |
| A: Wikipedia（日英）のみ   | 約$0.003/回 | 約$0.06/回 | 約$0.12/回 |
| B: A＋Web検索（5回と取得） | —           | 約$0.19/回 | 約$0.33/回 |
| C: 貼り付けたURL1件        | 約$0.002/回 | 約$0.03/回 | 約$0.06/回 |

## 決定（暫定）

- まず `claude-haiku-5-5` で、画面のないプロトタイプ（CLI）を使ってソースを比較する。
- 比較するのは Wikidata、Wikipedia（日英）、貼り付けURL、テキスト貼り付け、Web検索（ClaudeのWeb検索ツールか、無料枠のある検索API）。
- 判断の基準は [metrics](../spec/metrics.md#抽出の品質)。件数の多さではなく、適合率を優先する。

## ステップ4で決めること

1. 採用するソースの組み合わせ（標準と「深掘り」の分け方）
2. Web検索の提供元
3. `third_party` の線をグラフに出すか、出す場合の見せ方
4. Haikuで精度が足りない場合の扱い（Sonnetへの切り替えか、プロンプトでの補強か）

## 検討した代替案

- 最初から Opus で、Web検索も常に使う: 精度は高いが、月500円の予算に収まらない。

## 結果とトレードオフ

評価のための正解データ（10人分）を本人が作る手間がかかるが、「件数が多いから良い」という誤った判断を避けられる。
