# 0017 1ステップ＝1ブランチ＝1PR、再発防止は機械的な対策を優先する

- 状態: 採用
- 日付: 2026-11-15

## 背景

本人はレビュー役に回る。エージェントが詰まったときに同じ失敗を次のセッションで繰り返さないようにしたい。CLAUDE.md に注意書きを足すだけでは、増えるほど読まれなくなり、形骸化する。

## 決定

- 1ステップ＝1ブランチ＝1PRとし、完了条件のコマンドをすべて通してからPRを出す。マージは本人が行う。
- 同じエラーで3回失敗したら作業を止め、`docs/process/incidents/` に記録する。
- 対策は lintルール → テスト → スクリプト → AGENTS.mdへの追記 の優先順で選び、選んだ理由も記録する（[process](../spec/process.md#詰まったときの再発防止)）。

## 検討した代替案

- main に直接コミットする: 軽いが、巻き戻しにくく、レビューの単位がぼやける。
- 毎回本人に相談する: 確実だが、本人の手間が増え、自律的に進められない。

## 結果とトレードオフ

- PRの数は増えるが、1つずつが小さくなり、レビューしやすくなる。
