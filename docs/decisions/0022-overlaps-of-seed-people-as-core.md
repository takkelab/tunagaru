# 0022 好きな人たちの「重なり」を体験の芯にし、画面を一覧と棚にする

- 状態: 採用
- 日付: 2026-11-15

## 背景

本人と話して、次のことが分かった。

- 原点の体験は「自分の好きな人たち（SHE IS SUMMER の作詞者、南沙良さん）が、別々の記事や動画で同じ作家（吉本ばなな）を好きと言っていた」こと。本人は「自分が気づいていないだけで、この現象はもっと起きているのではないか」と考えている。
- 喜びは3種類ある。**答え合わせ**（やっぱり！）、**扉が開く**（読んでみたら面白かった）、**意外**（この人、こういうのも好きなんだ）。勧められたものが刺さるのは7割ほどだが、刺さらなくてもよい。
- 本人は記事で「好き」を見つけても、何も残さない。読んでいるときは、後で必要になると思っていないため。
- インタビュー記事を読むこと自体が楽しい。その人の考え方やルーツが分かるから。
- 重なりを見つけたら、その作品を読む・聴くことと、元の記事を読みに行くことをしたい。
- 起点にしたい好きな人は、10〜20人ほど。

[ADR 0008](0008-expanding-canvas-forward-only.md) の展開型キャンバスは、1人から芋づる式に辿る体験を前提にしている。この体験では、複数の起点の重なりは見えにくい。

## 決定

- **起点**: 本人が「好きな人」として追加した主体を起点と呼ぶ。主体は誰でもよい（作家、音楽家、俳優など）。「好き」の対象は、これまでどおり本と音楽の作り手に限る（[ADR 0002](0002-hybrid-sources-and-definition-of-like.md)）。
- **重なり**: 2人以上の起点から「好き」の線が来ている作り手。最初の画面（S3）に一覧で出す。
- **棚**: 起点ごとの「好きなもの」の一覧（S4）。1人しか挙げていないもの（「意外」）は、ここで見る。
- **根拠カード**: 引用と前後の文脈を見せ、元の記事・動画の該当箇所へ案内する（動画はタイムスタンプから再生する）。本文を読む楽しみは奪わない。
- **確かめるのは重なりの部分だけでよい**: 未確認の線も、「未確認」の表示つきで一覧と棚に出す。承認は、重なりのカードからその根拠をまとめて確かめる形を主にする。全件を承認する画面は作らない。
- **自分の好みは入力しない**。マークは、作品の「気になる」1つだけにする（[ADR 0023](0023-works-as-records-overlaps-by-creator.md)）。
- **外部リンク**は、設定で選んだ店やサービスの検索URLにする（初期値は Amazon と Spotify）。どちらもAPIは使わない。
- 展開型のグラフキャンバスは作らない。「なぜこれが出たか」を見せる画面として必要になったら、新しいADRで決める。

## 検討した代替案

- 展開型キャンバスのまま、重なりを強調表示する（ADR 0008）: 1人ずつ展開しないと重なりが現れず、10〜20人の起点を横に並べにくい。
- 「好きな作り手のN人が挙げている作品」のランキングを主にする: 最初のうちはほぼ全件が1人になり、順位に意味がない。「意外」も下に埋もれる。
- 自分の好みも入力して、三重の重なりを描く: 「やっぱり」は記録しなくても頭の中で起きる。本人は記録しない人なので、入力の手間は使われなくなる原因になる。
- 4種類のマーク（好き／気になる／試した／合わなかった）: 今の規模では使い分ける場面がない。

## 結果とトレードオフ

- 起点から何段も辿る体験は、最初の試作品にはない。重なった作り手を起点に追加すれば、同じことができる。
- 確かめていない線も表示されるので、誤った「好き」が棚に出ることがある。重なりのカードを確かめる段階で拾う。
- Cytoscape.js は当面使わない（[ADR 0011](0011-typescript-stack.md) の技術スタックのうち、この部分は保留する）。
