# 0024 引用は本文中の位置を探して照合し、動画は文字起こしの貼り付けから扱う

- 状態: 採用
- 日付: 2026-11-15

## 背景

[ADR 0004](0004-quote-verification-and-unverified-edges.md) では、LLMの引用が「正規化した本文の部分文字列」であれば通し、そうでなければ捨てていた。

本人の好きな人の「好き」は、記事だけでなく動画（「南沙良の好きなモノ」のような紹介動画、インタビュー動画）にもある。動画の文字起こし、特に自動字幕には誤字が多い。LLMは引用を写すときに誤字を直してしまうので、完全一致では本物の引用まで捨ててしまう。

字幕の取得には `yt-dlp` が使えるが、YouTube の利用規約では自動的な手段でのアクセスが制限されている。また、YouTube 側の変更でよく動かなくなる。公式の YouTube Data API では、動画の所有者でないと字幕を取得できない。

## 決定

- **照合は、位置を探す方式にする**（[data: 引用照合](../spec/data.md#引用照合)）。
  1. LLMの引用を手がかりにして、本文中の該当範囲を探す。正規化後に完全一致すればその範囲を使う。一致しなければ、あいまい一致で最も近い範囲を探す。
  2. あいまい一致で通すのは、類似度が閾値以上で、かつ、その範囲に相手の名前か別名が含まれる場合だけにする。
  3. 根拠として保存し表示するのは、**LLMの出力ではなく、本文側の文字列**（とその位置）にする。LLMが作った文字列は画面に出ないので、捏造を防ぐ仕組みは保たれる。
- **状態の扱いは ADR 0004 を引き継ぐ**: 照合を通った線は `unverified`、本人が確かめると `approved` になる。見た目は、破線ではなく「未確認」の表示にする（[ADR 0022](0022-overlaps-of-seed-people-as-core.md)）。
- **動画は、文字起こしの貼り付けから扱う**。YouTube の「文字起こしを表示」の内容をコピーし、動画のURLと一緒に貼る。タイムスタンプを読み取り、根拠に再生の開始秒を持たせる。根拠のリンクは `&t=<秒>s` つきにする。
- 文字起こしの本文は発言者の著作物なので、記事の本文と同じく、ローカルのキャッシュ（`data/texts/`）にだけ置く。テストには自分で書いた架空の文字起こしを使う（[ADR 0019](0019-public-repository-safeguards.md)）。
- `yt-dlp` による自動取得と、Whisper による文字起こしは、今は作らない。必要になったら、利用規約を確かめたうえで新しいADRで決める。

## 検討した代替案

- 完全一致のまま、正規化の規則を増やす（ADR 0004）: 自動字幕の誤字は規則で吸収できない。
- あいまい一致だけを足し、LLMの引用をそのまま保存する: LLMが言い換えた文字列が根拠として残り、捏造との区別がつかなくなる。
- 最初から `yt-dlp` で字幕を取る: 手間はなくなるが、規約上のリスクがあり、壊れやすい。
- 動画は後回しにする: 好きなものの紹介動画は、まとまった根拠が一度に取れるので、早く使えた方が価値が大きい。

## 結果とトレードオフ

- 動画1本ごとに、文字起こしをコピーして貼る手間がかかる。
- 自動字幕には話者の区別がないので、インタビュアーの発言を本人のものとして拾う誤りが、記事より増える。根拠カードに前後の文脈を出し、その場面から再生できるようにして、確かめやすくする。
- あいまい一致の閾値は `src/domain/` の定数にし、表形式のテストで固定する。閾値が低すぎると誤りが通り、高すぎると本物を捨てる。破棄率は [metrics](../spec/metrics.md#抽出の品質) で監視する。
