# 0009 作品は属性、グループは別ノード

- 状態: 採用
- 日付: 2026-11-15

## 背景

入口は「好きな本・曲」だが、曲には作詞・作曲・歌唱・バンドなど複数の作り手がいて、作家が一意に決まらない。また「好き」の対象が作品の場合もある（例: 「カラマーゾフの兄弟が好き」）。バンドの場合、「好き」を発言するのはほとんどがメンバー個人である。

## 決定

- ノードは人物とグループだけにする。作品は属性（`work`）として持つ。
- 作品で検索した場合は、作り手の候補を役割つきで示し、本人に選んでもらう。
- 「作品が好き」という発言は、その作者への線に変換し、作品名を根拠に添える。
- グループとメンバーは別ノードにする。線は発言した個人から引き、グループを展開したときはメンバーの線も集約して表示する（[screens](../spec/screens.md#グループ)）。

## 検討した代替案

- 人物と作品の両方をノードにする: 正確だが、ノード数が倍以上になり、画面が混雑する。
- 入口を人名のみにする: 作品から辿れない。
- グループに集約する: 簡単だが、誰の発言かが失われる。

## 結果とトレードオフ

- 「作品が好き」という情報は、作者単位に丸められる（作品名は根拠に残る）。
