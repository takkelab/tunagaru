# 0021 main をブランチ保護し、CIの通過を必須にする

- 状態: 採用
- 日付: 2026-11-15

## 背景

[ADR 0017](0017-step-branch-pr-and-mechanical-prevention.md) では「1ステップ＝1ブランチ＝1PR、マージは本人が行う」と決めた。しかし、これを守らせているのは今のところ AGENTS.md の文章と lefthook だけである。

- Claude Code は本人の `gh` の認証情報で動くので、GitHub から見ると本人（リポジトリの管理者）と区別できない。main に直接 push することも、CI が落ちたPRをマージすることも、技術的にはできてしまう。
- lefthook は手元のフックなので、`--no-verify` や別の環境からの push では動かない。
- 手元の `pnpm check` は Windows だけで動いている。Ubuntu で落ちる変更は、CI でしか見つからない。

## 決定

main に次のブランチ保護を設定する。

- **CI の通過を必須にする**: `check (ubuntu-latest)` と `check (windows-latest)` の両方が成功しないとマージできない。
- **ブランチを最新にしてからマージする**（strict）: 古い main の上で通った CI では、マージできない。
- **管理者にも適用する**（enforce_admins）: 本人の認証情報で動くエージェントにも、同じ制限がかかるようにするため。
- **force push とブランチの削除を禁止する**: 履歴の書き換えを防ぐ。秘密情報を push してしまった場合も、履歴の書き換えではなくキーの無効化で対応する（[ADR 0019](0019-public-repository-safeguards.md)）。
- **レビューの承認は必須にしない**: 利用者は本人だけで、GitHub では自分のPRを承認できない。必須にすると、何もマージできなくなる。

## 検討した代替案

- 保護しない: 設定の手間はないが、ADR 0017 の運用が文章だけで守られることになる（[ADR 0017](0017-step-branch-pr-and-mechanical-prevention.md) の「機械的な対策を優先する」に反する）。
- 管理者を除外する: 本人が緊急時に直接直せるが、本人の認証情報で動くエージェントも除外されてしまう。
- レビューの承認を必須にする: 1人の運用では成り立たない。

## 結果とトレードオフ

- 本人も、main に直接 push できない。どんな小さな修正でもPRを作り、CI（Ubuntu と Windows で数分）を待つ必要がある。
- 緊急時には、本人が GitHub の設定画面から一時的に保護を外せる。外した場合は、元に戻すこと。
- CI のジョブ名（`check (ubuntu-latest)` など）を変えるときは、ブランチ保護の必須チェックも合わせて変える。変えないと、どのPRもマージできなくなる。
