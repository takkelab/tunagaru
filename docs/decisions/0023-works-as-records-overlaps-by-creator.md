# 0023 作品は記録として持ち、重なりは作り手の単位で数える

- 状態: 採用
- 日付: 2026-11-15

## 背景

[ADR 0009](0009-works-as-attributes-groups-as-nodes.md) では、作品を人物の属性（`work`）として持ち、作り手を1人に決めていた。別の相談では、逆に「人→作品」を基本のデータにする案も出た。

本人の体験では、南沙良さんの紹介で吉本ばななの『キッチン』から入ったが、強くは刺さらなかった。その後、自分で他の作品も読み、『違うことをしないこと』が良かった。つまり、**勧められた作品は入口で、行き着く先ではない**。一方で、本人が「気になる」を付けたいのは、作家でも記事でもなく、**作品**だという。

また、曲には作詞・作曲・歌唱などの複数の作り手がいるので、作り手を1人に決める形では表せない。

## 決定

- **重なりは、作り手（人物・グループ）の単位で数える。** 「作品が好き」という発言は、その作り手への線にし、作品を根拠に添える（ADR 0009 の考え方を引き継ぐ）。
- **作品は、ノードではないが、独立した記録として持つ。** 作り手とは多対多にし、役割（著者、作詞、作曲、歌唱）を付ける（[data](../spec/data.md#テーブル)）。
- 作品には「気になる」を付けられ、外部リンク（店・配信サービスの検索）を出せる。
- 重なりのカードには、「誰がどの作品を挙げたか」を並べる。どれから入るかの手がかりにするため。作品名が出ていない場合は、Wikidata にある代表作を「入口の候補」として、根拠とは分けて示す。
- **作品の名寄せ**: 作品名だけでは決めない（「キッチン」のような普通名詞があるため）。作品名と作り手の名前の組で Wikidata を検索し、作品の作り手（P50 著者、P676 作詞者、P86 作曲者、P175 演奏者）が一致する候補に限る。1件に決まらなければ、本人が選ぶ（[ADR 0005](0005-entity-resolution-by-wikidata-qid.md) と同じ扱い）。
- グループとメンバーを別のノードにすることと、線は発言した個人から引くことは、ADR 0009 のとおりとする。
- **ソロプロジェクトの名義は、グループではなく本人の別名として扱う**（例: 一人で活動するアーティストの名義）。本人が関心を持っているのは作詞をしているその人で、調べるときは名義で検索するため。記事が名義で書いていても、別名からその人に寄せる。

## 検討した代替案

- 「人→作品」を基本のデータにして、人と人の線を計算で出す: 「吉本ばななが好き」のように作品名のない発言が多く、作品だけでは重なりが作れない。
- 人物と作品の両方をノードにする: 画面の主役が重なりの一覧になったので、ノード数の問題はなくなった。ただ、重なりを作品の単位で数えると、同じ作家の別の作品を挙げた2人が重ならない。
- 作品を属性のまま、作り手を1人に限る（ADR 0009）: 曲の作り手を表せず、「気になる」を付ける先がない。

## 結果とトレードオフ

- 同じ作家の別々の作品を挙げた2人は重なりとして出る。どの作品が挙がったかは、カードの中で分かる。
- 作品の名寄せは、作り手が決まってから行うので、作り手の名寄せを先に済ませる必要がある。
