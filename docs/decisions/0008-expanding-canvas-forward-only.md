# 0008 展開型キャンバスで、表示は順方向のみ

- 状態: 採用
- 日付: 2026-11-15

## 背景

芋づる式に3〜4段階展開すると、ノードが数百個になり、線が絡まった毛玉（ヘアボール）になる。また、「Bを好きな人」（逆方向）は、大御所の場合に数百〜数千人になり、どこから辿っても同じ人物に行き着いてしまう（ハブ問題）。

## 決定

- クリックしたノードだけを展開する、力学レイアウトのキャンバスにする。折り畳み、ピン留め、経路の強調表示、「+N」バッジを持ち、一度に出すのは最大20件とする。
- 表示は「Aが好きな人」（順方向）のみ。データ上は逆引きのクエリもできるようにしておく。

## 検討した代替案

- 自分中心の放射状表示: 毛玉にはならないが、全体像と合流が見えない。
- 横に伸びる木構造: 読みやすいが、合流（AもCもXを好き）を表現しにくい。
- 両方向を表示し、大御所は抑制する: 発見は増えるが、画面と実装が複雑になる。

## 結果とトレードオフ

- **リスク**: 順方向のみだと、時代を過去へさかのぼるほど線が減り、行き止まりになりやすい。行き止まりのノードでは調査ボタンを強調して補う（[screens](../spec/screens.md#展開のルール)）。行き止まりが多すぎると感じた場合は、逆方向の表示を新しいADRで再検討する。
